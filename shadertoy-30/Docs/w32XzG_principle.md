# w32XzG globules bubbles 原理

## 效果目标

这是一个完全由屏幕空间 Shader 生成的气泡洞效果。它没有模型、Buffer 或贴图，核心是在二维屏幕上反复修改参数化坐标，让像素坐标被一组移动中的圆形区域逐步推开。

## 核心算法

1. **屏幕坐标归一化**
   - U = (2 * fragCoord - iResolution.xy) / iResolution.y 将屏幕坐标变成保持纵横比的中心坐标。
   - 除以分辨率 Y，而不是 X，保证圆形洞在不同宽高比下仍然是圆。

2. **单个气泡的参数化**
   - push_hole 先计算 D = pushDistance / length(U)。
   - 当 D > 1 时，像素不在气泡影响范围内，返回 0。
   - 否则通过 pow(1 - pow(D,n), 1/n) 得到一个径向推开系数 v。
   - U = P + v * V 把当前像素沿气泡中心方向重新映射，形成洞的边缘和内部。

3. **重复叠加**
   - 主循环执行 200 次。
   - 每个气泡中心 P 由两组不同频率的正弦和余弦组成，因此气泡会以复杂但连续的轨迹运动。
   - 每次循环都对当前参数化坐标继续推开，最终形成相互挤压的 globules 图案。
   - 这不是 Ray Marching，而是迭代的坐标变形与轮廓累积。

4. **轮廓与颜色**
   - fwidth(D) 估计屏幕空间导数，使轮廓宽度与分辨率相关。
   - d 保存最小轮廓距离，最后通过 smoothstep 软化边缘。
   - hue(i/100) 用余弦调色板为气泡赋予彩色渐变。
   - O == O - O 是利用初始黑色输出进行首次着色的技巧，HLSL 中改写为等价的 all(O == (O - O))。

## 交互参数

- 鼠标 Y：当鼠标输入有效时控制洞的半径/推开距离。
- 鼠标 X：控制推开后恢复到原始参数化的斜率。
- _STTime：控制气泡中心的运动。
- 200：气泡迭代次数，减少会降低密度和复杂度，增加会提高成本。

Unity 端不能直接把整个编辑器窗口的鼠标像素坐标传给 iMouse。Bootstrap 先用 Camera.ScreenToViewportPoint 转成当前画布的 0..1 坐标，再映射到 960x540；鼠标在画布外时传零，避免编辑器窗口位置改变 Shader 参数。

## GLSL 到 HLSL 的移植要点

- vec2/vec4 显式转换为 float2/float4。
- fract 转为 frac。
- GLSL 的可写全局 _D 改为 PushHole(..., out depth)，每次调用的结果完全等价且避免跨语言全局状态差异。
- GLSL 向量相等判断转为 HLSL 的 all(...)。
- 保留原始 Y 轴方向，不额外翻转坐标。
- iMouse 使用画布局部坐标，而不是 Unity 屏幕绝对坐标。
- 循环显式初始化 i = 1，对应原始 i++ < 2e2 的第一轮取值。
- ShaderLab 保留 ForwardUnlit 和统一的 DepthOnly pass。

## 限制

效果是纯屏幕空间图形，无法提供真实几何、碰撞或物理交互。若用于游戏，应将鼠标参数替换为 C#、Timeline、VFX 或 gameplay 系统写入的控制量。
